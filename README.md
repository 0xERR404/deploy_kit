# deploy_kit

Меню для настройки self-hosted сервера. Модули выполняются по порядку,
каждый идемпотентен (повторный запуск пропускает уже пройденные шаги).

## Запуск

```bash
curl -fsSL https://raw.githubusercontent.com/0xERR404/deploy_kit/main/install.sh | sudo bash
```

Скачает всё в `/var/lib/deploy_kit` и откроет меню. Повторный запуск —
той же командой или напрямую:

```bash
sudo bash /var/lib/deploy_kit/menu.sh
```

## Модули

1. **Базовая настройка** — DNS, swap, BBR, auditd, sudo-пользователь, SSH,
   ufw, fail2ban, apparmor, NTP, автообновления/автоочистка/автоперезагрузка,
   health-checker.
2. **Docker + Caddy** — Docker Engine, Compose, общая сеть `dk_net`, Caddy
   как единственная точка входа наружу (один корневой домен, без поддоменов
   у сервисов — см. `dk_hostname`/`claim_root_domain` в common.sh).
3. **Pocket ID** — OIDC-провайдер (замена Authelia), только для SSO
   Vaultwarden/Forgejo с хабом — не форвард-прокси, произвольные пути не
   защищает (см. комментарии в common.sh). Свой поддомен (единственное
   исключение из "всё на одном домене" — техническое ограничение самого
   Pocket ID, APP_URL не может содержать путь).
4. **NEXUS404 Interface** — свой хаб (замена Homer), единственная внешняя
   точка входа на корневом домене, карточки сервисов появляются сами по
   ходу установки остальных модулей (add_hub_card), сервисы — в iframe
   или как виджеты через API, в одном окне.
5. **ntfy** — push-уведомления, во внутренней сети, наружу не торчит.
6. **Beszel** — мониторинг ресурсов, в хабе — только CPU/RAM/сеть/диск
   через API, не полный веб-интерфейс.
7. **Vaultwarden** — менеджер паролей, веб-морда выключена, доступ только
   через клиенты по секретному пути под доменом хаба.
8. **Forgejo** — git-сервер, OIDC SSO через Pocket ID.
9. **Vikunja** — в разработке. Задачи + канбан.
10. **Navidrome** — в разработке. Музыка.
11. **Syncthing** — в разработке. Синхронизация файлов.
12. **Remnawave** — в разработке. VPN-панель.
13. **Cheevoscope** — статистика игровой библиотеки (Steam + RetroAchievements,
    изначально github.com/0xERR404/cheevoscope, перенесён целиком внутрь
    хаба на stdlib), виджет: вкладки Steam/RetroAchievements/Общая
    статистика, плитка игр с обложками, редкость и heatmap активности —
    весь целиком внутри хаба (04_nexus404.sh), без отдельного контейнера.
14. **WalletScope** — свой лёгкий сервис учёта финансов в рублях (карта +
    депозит, переводы между ними, курсы USD/EUR/BTC/ETH) — весь целиком
    внутри хаба (04_nexus404.sh), без отдельного контейнера.
15. **MemoScope** — свой лёгкий блог/заметки: посты с картинкой и лёгким
    форматированием (жирный/курсив/подчёркнутый, заголовки, списки),
    2 колонки на ПК с masonry-раскладкой по реальной высоте — тоже
    целиком внутри хаба, без отдельного контейнера.
16. **Итоговая сводка** — короткий отчёт по всем установленным модулям,
   без своих шагов/STATEFILE, безопасно запускать когда угодно.

## Структура

```
install.sh    — curl-установка, качает всё остальное, сверяет SHA-256
menu.sh       — меню
common.sh     — общие переменные и хелперы (is_done, retry_apt, notify_send,
                dk_pocketid_oidc_register_client — регистрация OIDC-клиента...)
modules/      — пронумерованные модули пайплайна (в меню)
tools/        — вспомогательные скрипты (НЕ в меню), например test_ntfy.sh
```

## Диагностика ntfy

```bash
sudo bash /var/lib/deploy_kit/tools/test_ntfy.sh
```

Прогоняет все хуки уведомлений подряд (кроме SSH-входа — его надо просто
зайти по SSH ещё раз).

## Добавить новый модуль

Если позиция УЖЕ зарезервирована под roadmap (сейчас 9–15, см. выше):

1. Написать `modules/NN_имя.sh` (номер — как в `MENU_ITEMS`), используя
   функции/переменные из `common.sh` — можно смотреть на
   `08_forgejo.sh`/`07_vaultwarden.sh` как на образец.
2. В `menu.sh` заменить путь у соответствующего пункта `MENU_ITEMS` с
   `$MODULES_DIR/_planned.sh` на новый файл, убрать из заголовка
   " — в разработке".
3. `download "modules/NN_имя.sh"` + SHA-256 в `install.sh` (заглушку
   `_planned.sh` из списка `download` не убирать — она используется
   остальными ещё не готовыми пунктами).

Если модуль новый и НЕ в roadmap выше — просто следующий свободный номер
после последнего сервис-модуля, сдвинуть номер сводки (сейчас 16) и файл
`modules/16_summary.sh` на освободившийся следующий номер.

## SHA-256

При любом изменении `menu.sh`, `common.sh`, любого файла в `modules/`
или `tools/` — пересчитать и обновить `EXPECTED_SHA256` в `install.sh`:

```bash
sha256sum menu.sh common.sh modules/*.sh tools/*.sh
```

## Стиль

Код и комментарии на русском. Каждый модуль: `enable_full_logging` первой
строкой, шаги вида `step<N>_<M>` в STATEFILE, `is_done`/`mark_done` для
идемпотентности. Шаги внутри модуля идут подряд без остановки —
`pause_step` вызывается только в `menu.sh`, на границе «модуль → меню»
(перед `clear()`), чтобы финальная сводка модуля (пароли, адреса) не
исчезала с экрана мгновенно.
